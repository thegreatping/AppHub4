How quarter transitions work (and the GA quarter-close plan)

Topic Behavior
Quarter switch (Q2 -> Q3) The grid automatically switches to the newest AY/QUARTER present in SCORECARD_CORE the moment the pipeline writes Q3 rows. No code deploy or admin action required.
Carry-over of overrides / RM Score / notes Each quarter has its own SCORECARD_CORE row (keyed on PROPERTY_KEY + AY + QUARTER). Overrides, locks, RMSCORE, and NOTES do not carry forward from Q2 into Q3 - Q3 starts fresh. Q2's edits are preserved on the Q2 row.
Compare Quarters tab New tab (next to Scorecard / Fall Forecast). Pick any two quarters A and B present in SCORECARD_CORE and see per-property deltas on every measure plus PRERM / Leadership Total / Maintenance Total / Overall. Green = improvement, red = regression. Read-only; respects your role scoping.
Historical quarters stay editable (during beta) For the beta window, Q2 2026 (which is already paid out) is intentionally left editable so you can experiment with the override / lock / NOTE flows without changing current quarter data. Please do not treat test edits as actual corrections.
Quarter close (planned for GA) At GA we will add an admin-only "Close Quarter" button. Closing a quarter:
  • Sets SCORECARD_CORE.FLAG_FINAL = 1 on every row for that AY/QUARTER (new schema column).
  • All write endpoints (override toggle, measure patch, RM Score, NOTES) return 403 "This quarter is closed - contact admin to re-open".
  • Grid continues to display the closed quarter as read-only; the Compare Quarters tab is unaffected.
  • Admins get a "Re-open Quarter" button (confirmation gated) for emergency corrections.
  • Every close / re-open is logged in control.SCORECARD_TABLE_MANAGER_AUDIT so there is a paper trail for finance.
Not in beta scope. No action required from testers now.
