The Central Table
DB_APP_SUPPORT.dbo.Emp_Core
149 cols, PK=EMPLOYEE_KEY Built + Backfilled (7,185 rows)
Single source of truth. Replaces WH_STAGING.EMPLOYEE_F, WH_STAGING.EMPLOYEE_0, DB_APP_SUPPORT.xtemp.EMPLOYEE_F, and DB_APP_SUPPORT.dbo.EMPLOYEE_0 outright (Item #16) -- not a shadow of them.

Adopts the existing per-field lock-bit convention (*_LOCKED columns) from the old EMPLOYEE_0, since Emp_Core is now the bidirectional/EDM table itself.

EMPLOYEE_METRICS and EMPLOYEE_FACTS stay separate (date/vertical fact grain) -- Emp_Core feeds a daily snapshot into each, it does not absorb them.

See EMP_CORE_SCHEMA_DOC.html for the full column-by-column source/update-type reference.
→ AppHub EDM / Other Consumers
Readers-first migration in progress
No shadow-then-flip for this path. Consumers of the old EMPLOYEE_F/EMPLOYEE_0 migrate to Emp_Core one at a time, lowest-risk first. AppHub's own login/security lookup migrates last, only after every other consumer has burned in. Legacy EMPLOYEE_F_COMBO_SP is disabled only once nothing reads its output anymore.
→ AppHub 4.0 EDM "Emp Tables" Module
Read-only browser i-3-26 / i-3-27 COMPLETE 2026-09-16/17
Dedicated EDM sub-module (Employee Data Manager → Emp Tables) with a PDM-style browsable table per pipeline table: sortable/multi-select-filterable columns, category+A-Z detail slideout, Excel export. Covers Emp_Core, Emp_Core_Staging (Processing Output), control.EMP_PIPELINE_RUN_LOG (Processing History), every Emp_Import_* landing/snapshot table, Emp_Employee_Keys, Emp_Key_Resolution_Staging, Emp_Core_Retire_Staging, EMP_TITLE_OVERRIDES, EMP_PROPERTY_ASSIGNMENTS, and control.EMP_PROCESSING_RULES. Also supports adding arbitrary new tables on-the-fly from the UI (validated against a DB-engine whitelist, persisted server-side) so new pipeline tables can be exposed without a code deploy.
