What This Project Is

Rebuilding the legacy Paycom-driven employee data pipeline (EMPLOYEE_F_COMBO_SP_FABRIC.sql, a 986-line T-SQL stored procedure) as a modern Python Fabric notebook: NB_EMP_PIPELINE (de_remediation/_nb_emp_imports/NB_EMP_PIPELINE.py, ~2,800+ lines).

Target output table: Emp_Core (persistent, incrementally merged) -- replaces legacy WH_STAGING.dbo.EMPLOYEE_F (full truncate+rebuild every run) as the source of truth for employee data across AppHub, LEO exports, security groups, CasaPerks, and more.

Non-negotiable ground rule: legacy is always the source of truth. "Close enough" or a single matching metric is never accepted as proof of correctness -- every discrepancy is found and explained via row-level, column-level, byte-for-byte diffs.

Architecture at a Glance

Sources (Paycom SFTP, AD export, EDM reference tables) → Import (dedicated Emp_Import_* landing/snapshot tables, isolated from legacy) → Processing (config load, title overrides, key resolution, main join, rules, Entrata/LEO fields, assemble + merge) → Emp_Core (persistent, incrementally merged, single source of truth) → Exports (WH_PROD2, AD/LEO/CasaPerks/GraceHill feeds -- not yet built). See the Diagram view for the full table-by-table breakdown.

9 Real Bugs Found & Fixed During Parity Validation

  1. Case sensitivity -- SQL is case-insensitive by default, Python == is not.
  2. PROPERTY_KEY resolution -- had to replicate the exact legacy PAYCOM_IMPORT_LOAD_SP algorithm.
  3. Stale actives never retired -- Emp_Core is incremental, legacy was full-rebuild; fixed with an explicit retire pass.
  4. 4,153 stale leftover rows -- an active-count match masked a much bigger row-count defect; fixed with a real DELETE.
  5. POSITION/PAYCOM_POSITION field swap -- the single biggest bug, collapsed most remaining mismatches once fixed.
  6. ctx.cfg["EMPLOYEE_KEYS"] staleness -- new hires' keys were invisible to Main Join within the same run.
  7. Title overrides never reached Main Join -- only patched an unused config table.
  8. FLAG_TITLE_MATCH NULL-semantics bug -- Python or-chains don't replicate SQL NULL propagation.
  9. EMAIL NULL-semantics bug -- same category of mistranslation for ISNULL(WORK_EMAIL, AD_LOGIN).

Plus a self-caught bug in the validation script itself: it had been .upper()-normalizing comparisons, which could have masked real case-format bugs.

Known Open Items

  • i-3-30 (Pre-Hire key-minting) -- PROCESSING_KEY_RESOLUTION only mints/refreshes keys from Paycom MAIN rows, never from the Pre-Hire xlsx sources. A never-before-seen Pre-Hire-only employee currently gets their key only because legacy EMPLOYEE_KEYS_SP still originates one. Must be built before Phase 6 disables that legacy SP; not urgent before then.
  • i-3-24 lock verification needs a real test case (a genuine lock set in AppHub, or a deliberate test row) before it can be marked truly validated.
  • EXPORT phase (13 targets) has not been designed/built yet -- the next major body of work now that i-3-28 no longer blocks cutover planning.
  • Checklist HTML has a known duplicate-ID bug (i-3-28/i-3-29 each appear twice) -- cosmetic, not yet cleaned up.
