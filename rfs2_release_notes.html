Rent Forecasting 2.0 -- Feature Update

Development cycle ending July 31, 2026  •  Internal release notes
Over the past ~2 weeks, Rent Forecasting 2.0 received a significant round of UI, stability, and calculation improvements. Below is a complete summary of everything that landed, organized by category.
Stability & Bug Fixes 4 items
Fix
resetKpis() crash on property change
The function was calling .textContent on elements that no longer existed in the DOM, causing all data loads to silently fail when switching properties. Fixed with null-guards throughout.
Fix
SVG chart markup corruption
A prior edit accidentally merged a closing <div> tag with an SVG opening tag, breaking both the Leasing Trend and Rate Trends charts. Both chart blocks were manually corrected and validated.
Fix
Duplicate CSS rules in bottom section
.stkh-sec and .comps-sec were duplicated during a layout refactor, causing unpredictable sizing. Duplicate rules removed.
Fix
Comps table expanding the page
The market comps table had no scroll cap, causing the bottom section to grow taller than the viewport on properties with many comps. Fixed with max-height: 320px on the comps scroll container.
UI & Layout Improvements 7 items
UI
Floorplan custom dropdown with bed count
The floorplan selector was converted from a plain <select> to a styled custom dropdown matching the property selector. Each floorplan item shows its bed count badge (e.g. 118bd), making it easier to identify at a glance.
UI
Editable tier panel headers renamed
The two editable columns in the Renewals & New Leases tier table were relabeled to Renewal Reforecast and New Lease Reforecast for clarity.
UI
Tier section height reduced 30%
Default max-height for the renewals/new leases tier scroll containers reduced from 240px to 168px, leaving more room for charts and the bottom section.
UI
SVG chart height reduced 10%
Both chart viewBoxes (Leasing Trend and Rate Trends) were trimmed ~10% vertically, and the default wrapper height set to 280px -- reducing blank space without losing data legibility.
UI
Bottom section: side-by-side layout
The Market Comps table and the Stakeholder charts panel now sit side-by-side in a flex row, filling the available viewport height rather than stacking vertically.
UI
Chart Focus mode (67vh overlay)
A Focus button on the Stakeholder chart panel expands the charts section to a 67% viewport-height overlay fixed to the bottom of the screen. Clicking Back restores the normal layout -- designed for quick deep-dives without leaving the page.
UI
Tier section 2-state expand button
A toggle button on the Renewals & New Leases section header cycles between Default (truncated) and Expanded (full height) views. State resets to default on property change, but persists when switching floorplans within the same property.
Plan Use -- New DB-Backed Feature 6 items
Data
New table: FORECAST_FP_INDUCEMENT
Created in DB_APP_SUPPORT to store per-floorplan planned inducement/concession values. Keyed on (FORECAST_KEY, FLOORPLAN_KEY) -- one row per floorplan per plan. Includes full CRUD with audit fields (created by, dates).
Data
GET / POST /api/fp-inducement endpoints
Two new API endpoints let the front-end read and write a single floorplan's Plan Use value. POST upserts on the unique key, so the same call handles both new entries and updates.
Data
GET /api/fp-inducements (bulk)
A bulk endpoint returns all FP inducement values for a given forecast in a single call, used to pre-populate the client-side cache when a property is loaded.
Data
Clone plan copies FP inducement rows
When cloning a reforecast plan, all FP inducement rows from the source plan are automatically duplicated to the new plan -- no need to re-enter concession values.
Feature
FP Plan Use -- sticky per-floorplan input
Each floorplan now has its own annual concession dollar input (FP Plan Use). Values are loaded from the DB when you select a floorplan and auto-saved after 800ms of inactivity (debounced). Switching floorplans shows each one's saved value.
Feature
Client-side FP inducement cache (_fpPuCache)
All FP Plan Use values for the current property + plan are bulk-loaded into a JS cache on property/plan select. Switching between floorplans reads from cache (no DB round-trip). Cache is updated immediately on input changes, and cleared on property or plan change.
NER W/Plan Calculation Logic 4 items
Calc
Unified _recalcAll() function
A single function now drives both the Floorplan NER w/plan and the Property NER w/plan columns. It runs any time a Plan Use value changes, keeping both metrics in sync without double-counting.
Calc
FP NER w/plan -- direct FP math
Calculated purely from the current floorplan's actual + forecast lease pool. The annual FP Plan Use is converted to a per-month concession and subtracted from each forecast lease's NER, then blended with actuals using the FP's total lease count as the denominator.
Calc
Property NER w/plan -- sum of ALL FP concessions
Starts from the property-wide forecast NER (all floorplans), then subtracts the monthly equivalent of all floorplan Plan Use values combined, plus the Prop Plan Use:
Prop NER w/plan = forecast_ner - (Sum of all FP Plan Use / 12) - (Prop Plan Use / 12)
Concessions across multiple floorplans all roll up into the property-level metric -- and the Property NER w/plan only updates when a Plan Use value is actually edited, not when you flip between floorplans.
Calc
W/Plan columns show dash when no inputs set
If both Prop Plan Use and all FP Plan Use values are zero/empty, both w/plan columns display -- instead of repeating the same value as the Fcst column, keeping the display clean.
